# 07. 検証

「できたつもり」を防ぐため、何をどう確かめ、どうなれば合格かを先に決めておきます。
検証は5種類：**データ／体験／性能／使いやすさ（アクセシビリティ）／既存を壊していないこと**。

## 1. 出発点（現在の数値）

今回の調査で実測した値です。フェーズ1完了時に同じ項目を再計測し、改善を数字で示します。

|---|---|---|
| 探索UI（銀河）から到達できる作品 | 21 / 41 | 41 / 41（データ上） |
| 定義のある概念 / 参照されている概念 | 10 / 73 | 全参照が定義済み |

| 時間が数値で持たれている作品 | 0 / 41 | 41 / 41 |

## 2. データの検証（自動）

`tools/atlas/validate.mjs` が毎回確かめます。**エラーが1件でもあれば生成物を更新しません。**

| 区分 | 確認内容 | 扱い |
|---|---|---|
| ID | 重複なし、形式どおり、公開済みIDの削除・改名なし（前回の生成物と比較） | エラー |
| 参照 | すべてのエッジ・親・シリーズ参照の相手が存在 | エラー |
| 必須項目 | 公開中の作品：シリーズ、URL、時間、問い1以上、概念2以上、レンズ1以上 | エラー |
| URL | 作品・ページの `url` のファイルが実在 | エラー |
| 時間 | start ≤ end、精度あり、-138億年〜現在＋未来枠の範囲内 | エラー |
| 横断エッジ | `why` があり20字以上、`origin` が `curated` | エラー |
| 件数の急減 | 取り込み件数が前回より5%以上減った | エラー（既存ファイルの形が変わった疑い） |
| 孤立 | どのエッジにも現れない概念・問い・人物 | 警告 |
| 重複の疑い | 題・別名が一致する概念／同一人物らしい人物／同時期・同題の出来事 | 警告 |
| 翻訳 | 英語の無い題・問い | 警告（件数を報告） |
| 偏り | 1作品に概念が8以上、1概念に作品が15以上 | 警告（辞書の粒度見直し） |
| 到達性 | 各作品から2歩以内に別シリーズの作品へ行けるか | 警告 → フェーズ3で必須化 |

レポートは人が読める形（Markdown）でも出力し、プルリクエストで差分を確認できるようにします。

## 3. データの検証（人）

機械では確かめられない「内容の正しさ」です。

| 対象 | 確認者 | 観点 |
|---|---|---|
| 横断接続の `why`（40〜60本） | 作品の内容を知る方 | 事実として正しいか。こじつけでないか。作品本文の語り口と矛盾しないか |
| 大きな問い（12前後） | 編集責任者 | サイトの中心として妥当か。重複がないか |
| 概念辞書 | 編集責任者 | 用語が本文と一致しているか。まとめすぎ・分けすぎがないか |
| 年表の統合（哲学レイヤーと哲学史の重複など） | 編集責任者 | 同一とみなしてよいか |
| 時間範囲（41作品） | 編集責任者 | 作品の扱う範囲として違和感がないか |

歴史・思想に関する接続は誤りが信頼を損なうため、**自動で見つけた候補をそのまま公開しない**ことを工程上の決まりにします。

## 4. 体験の検証

### 4.1 課題シナリオ

試作（フェーズ2）を、初見の方5名程度（中高生・社会人・保護者または教員を含む）に使ってもらいます。

| # | 課題 | 合格の目安 |
|---|---|---|
| 1 | 説明なしで3分間、自由に触る | 3名以上が自発的に別シリーズの作品へ移動する |
| 2 | 「AIと教育について学べるものを3つ、別々のシリーズから見つけてください」 | 4名以上が2分以内に達成 |
| 3 | 「孔子と同じ頃に、世界で何が起きていましたか」 | 4名以上が時の河で答えられる |
| 4 | 「第5部と哲学シリーズ第1部は、なぜつながっているのですか」 | 4名以上が理由を自分の言葉で言える |
| 5 | 途中で「最初に見ていた作品に戻ってください」 | 全員が戻れる |
| 6 | 気になった問いをAIに渡す | 4名以上が迷わず完了 |

あわせて「迷った瞬間」「読めなかった文字」「意味の分からなかった線」を記録します。

### 4.2 公開後に見る数字

| 指標 | 意味 | 見方 |
|---|---|---|
| シリーズ横断率 | 1回の訪問で2シリーズ以上の作品ページを開いた割合 | 導入前後で比較（最重要） |
| 接続の利用 | `atlas_bridge_follow` の回数と、どの接続が使われたか | 使われない接続は理由文を見直す |
| ビュー別の利用 | 3ビューそれぞれの利用割合と滞在 | 使われないビューは入口を見直す |
| 作品ページへの送客 | Atlas から作品ページを開いた回数 | 探索が本文へつながっているか |
| AIへの受け渡し | `atlas_ai_handoff` の回数 | 探索が対話へつながっているか |

導入前の基準値は、現行の計測（`cta-tracking.js`）で取得できる範囲で、フェーズ3の前に記録しておきます。

## 5. 性能の検証

| 項目 | 合格基準 | 測り方 |
|---|---|---|
| 最初の表示データ | 圧縮後60KB以下 | 生成物のサイズを検証スクリプトで確認 |
| 操作可能になるまで | 中位スマホ・4G相当で2.5秒以内 | ブラウザの開発者ツール（回線・CPUを制限） |
| 描画の滑らかさ | PC 60fps、スマホ30fps以上（ドラッグ・ズーム中） | 開発者ツールのパフォーマンス記録 |
| 規模を増やした場合 | 作品200・出来事1,000・エッジ8,000の**水増しデータ**で上記を満たす | 生成スクリプトにテスト用の水増し機能 |
| 既存ページ | トップと年表の表示速度が導入前より悪化しない | 導入前後で同条件計測 |
| 時の河のズーム | 1763〜2024年の教育史51件が、最大ズームで重ならず選べる | 実データで目視。足りなければ最大倍率を調整 |

## 6. 使いやすさ（アクセシビリティ）の検証

| 項目 | 合格基準 |
|---|---|
| キーボードのみ | マウスなしで課題シナリオ2・3・5を完了できる |
| 読み上げ | VoiceOver／NVDA で、選択したノードの題・種類・接続数が読まれる |
| 動きを減らす設定 | 移動アニメーションが止まり、機能は同じ |
| コントラスト | 文字4.5:1以上、操作部品3:1以上 |
| 拡大 | 200%拡大で文字が重ならず、操作できる |
| タッチ | 操作対象44px以上 |
| canvas 無効時 | リスト表示だけで全作品に到達できる |

## 7. 既存を壊していないことの検証

**フェーズ1〜2（追加のみ）**

```bash
git diff --stat main...HEAD -- . ':!docs' ':!data/atlas' ':!tools/atlas' ':!assets/atlas' ':!atlas.html'
```

この出力が空であること（＝新規の場所以外に差分が無い）を、プルリクエストごとに確認します。
本設計資料のプルリクエストでは、差分は `docs/manabimap-next/` のみです。

**フェーズ3以降（既存ファイルを編集）**

| 確認 | 方法 |
|---|---|
| 主要ページが導入前と同じに見える | トップ・地図・年表・作品ページ各世代1本（計8ページ）を、PC幅・スマホ幅で画面撮影し、前後を比較 |
| リンク切れが無い | 全HTMLの内部リンクを機械的に検査 |
| 既存URLがすべて生きている | 導入前のURL一覧（HTML全件）が応答すること |
| 銀河の既存21作品 | 位置・レンズ所属・カード内容が導入前と一致（差があれば意図したものか確認） |
| 年表 | 出来事184件（160＋24）の表示件数・順序・画像が一致 |
| 英語版 | `en/` の4ページ＋作品ページで同様に確認 |
| コンソールエラー | 主要ページで0件 |

## 8. 完了の判定

各フェーズの完了条件は [08](08-implementation-plan.md) に記載します。共通の原則は次のとおりです。

- 自動検証がエラー0件。
- そのフェーズの合格基準を、**数字または画面で示せる**。
- 既存ページへの影響が、意図したものだけである。
